## Scenario, rule, and order

This backlog assumes that all 137,139 canonical issue records already have a
bundle generated in the format used on 2026-07-29. The generated corpus is
evidence that must be frozen; it is not yet immutable and is not automatically
validated editorial content.

Only two states are permitted:

- **DONE** — implemented and evidenced.
- **PENDING** — anything else.

The list deliberately splits controls that earlier documents combined under
one status. For example, the high-precision retention rules are DONE; topical
relevance is PENDING. Generation manifests are DONE; a reconciled
current-edition manifest is PENDING.

Priorities:

- **P0 required** — preserve data or prevent materially false evidence,
  unsupported law, broken identity, unlawful publication, or unreproducible
  releases.
- **P1 required** — necessary for professional digest quality and full-scale
  operation.
- **P2 good to have** — useful after the release gates work.

## P0 required — preserve and repair evidence

### P0-001 — Freeze the complete generated snapshot

**State: PENDING**

**Problem/evidence.** Re-runs historically overwrote reviewed bundle
directories; 985 of 3,010 analyzed paths had multiple research writes.

**Cause.** Generation target and canonical edition share one mutable directory.

**Action.** Create immutable object storage, Git/data commit references, and a
signed SHA-256 inventory for all 137,139 assumed bundles.

**Acceptance.** Exactly one frozen generated revision resolves for every issue
ID; restore test reproduces all hashes.

### P0-002 — Bind every assumed bundle to one canonical issue ID

**State: PENDING**

**Problem/evidence.** The measured snapshot has 1,561 non-empty `issue_id`
values among 1,705 digests.

**Cause.** Legacy bundles, including 69 measured bundles without `run.json`,
were permitted by a loose schema.

**Action.** Resolve each path to a registry record; quarantine collisions and
unresolved paths.

**Acceptance.** 137,139 unique bundle-to-issue bindings; zero inferred identity
from label alone.

### P0-003 — Replace positional source association

**State: PENDING**

**Problem/evidence.** The save loop filters rejected sources, while
`classify_retained_sources()` pairs compacted filenames with the unfiltered
source list by index. The two paths also iterate different collections
(`output.source_markdown` versus `output.result.source_documents`), so a
length divergence misbinds filenames even with zero rejections.

**Cause.** Parallel arrays have no durable source identity.

**Action.** Introduce an immutable source-decision record carrying source ID,
URL, title, text hash, path, origin, gate result, and classification.

**Acceptance.** Accepted–rejected–accepted contract tests preserve associations;
no production renderer accepts parallel metadata/filename arrays.

### P0-004 — Reconstruct edition source associations

**State: PENDING**

**Problem/evidence.** The code defect in P0-003 may have propagated into
generated indexes and manifests.

**Cause.** All downstream outputs use the same positional classification.

**Action.** Reconcile source frontmatter, audit entries, disk paths, URLs,
content hashes, and citations. Mark ambiguous edges; do not guess.

**Acceptance.** Zero orphan, duplicate, or ambiguous source IDs in any
publishable edition.

### P0-005 — Preserve generation manifests as immutable provenance

**State: PENDING**

**Problem/evidence.** Later fixes currently edit files described by the
generation manifest.

**Cause.** `run.json` represents both historical generation and current
directory integrity.

**Action.** Freeze `run.json` with the generated revision.

**Acceptance.** Generation provenance is byte-stable and never rewritten by an
editorial repair.

### P0-006 — Generate separate current-edition manifests

**State: PENDING**

**Problem/evidence.** Current measured scan found 48 missing inventory files,
130 SHA mismatches, 121 byte mismatches, 855 on-disk sources outside inventory,
154 retained-count mismatches, 166 declared-evidence-count mismatches, 169
evidence-list-length mismatches, 44 evidence filenames missing from disk across
24 bundles, 995 on-disk sources outside evidence lists, and source filename-set
differences across 172 bundles. Of 13,020 inventory entries, 12,309 are
absolute paths and 711 are relative.

**Cause.** Reviewer and repair changes are not represented as a new edition,
and `build_manifest()` inventories only the current `SaveRecord` paths, leaving
pre-existing rerun files outside the new inventory.

**Action.** Build `edition.json` from normalized source/claim/authority records
and disk/object storage; record change lineage.

**Acceptance.** Zero missing, extra, hash, byte, count, or evidence
discrepancies.

## Definition of “number-one quality”

The project may make a top-quality competitive claim only after all of these
are DONE:

- zero critical legal errors in release-gate samples;
- at least 99% claim support;
- at least 98% substantive legal correctness;
- at least 98% issue-versus-scaffold precision;
- at least 98% retained-source topical precision;
- at least 95% primary-authority recall;
- at least 99% authority normalization accuracy;
- at least 0.80 chance-corrected reviewer agreement (κ/α);
- zero structural, provenance, rights, or graph release violations;
- blind lawyer-task results that are reported, reproducible, and competitive;
- separate measured treatment/current-law performance before making a
  KeyCite-like citator claim.
